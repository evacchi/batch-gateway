Batch vs Live Traffic Isolation

Setup

ModelQwen/Qwen3-8B on 1× NVIDIA A100-80GB (max concurrency ~198 @ 4096 tokens)
Live trafficguidellm --profile concurrent at [5, 30, 50, 80] concurrent requests, 120s per phase, 60s idle between
Batch load5×1000 requests submitted at start + 5×1000 overlapping during first burst (~1500 tok/req, faker prompts)
EPPFlow control enabled (maxRequests: 50), optimized-baseline profile
Gateprometheus-budget, max_concurrency=50, fallback=0.0

Scenarios

Baseline

No batch stack installed. Pure live traffic only.

Sync (default)

Batch processor: per_endpoint=10, AIMD enabled. Out-of-box settings.

Sync (aggressive)

Batch processor: per_endpoint=100, AIMD disabled. Worst-case batch flooding.

Gated (async)

Async dispatch with prometheus-budget gate. Batch held back when GPU busy.

Analysis

With 5×1000 batch requests (5000 initial + 5000 overlapping during burst), batch workload stays active throughout all phases, providing sustained GPU pressure alongside live traffic.

Sync-default (per_endpoint=10, AIMD on): the processor limits itself to 10 concurrent inference requests and backs off on 429s. This self-throttling keeps batch impact minimal — TTFT is within ~5% of baseline at all concurrency levels. The built-in safety mechanisms work, but batch throughput is low.

Sync-aggressive (per_endpoint=100, AIMD off): without self-throttling, batch floods the GPU with up to 100 concurrent requests. This causes 25–60% TTFT degradation across all concurrency levels (83ms vs 55ms at conc=5, 107ms vs 86ms at conc=80). ITL nearly doubles (14–25ms vs 6–16ms). Successful live request counts drop significantly (81 vs 199 at conc=5, 701 vs 1138 at conc=80) — the GPU is serving batch instead of live traffic.

Gated: the prometheus-budget gate monitors vllm:num_requests_running and holds batch back when utilization exceeds max_concurrency=50. TTFT matches baseline at every concurrency level (<3% difference). The gate protects live traffic quality while still allowing batch to progress during idle phases.

Key takeaway: without the gate, aggressive batch dispatch degrades live traffic TTFT by 25–60% and halves throughput. The prometheus-budget gate eliminates this interference, keeping live traffic quality at baseline levels. The default processor settings (AIMD + low per_endpoint) also prevent degradation, but at the cost of very low batch throughput.
