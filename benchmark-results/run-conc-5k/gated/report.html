Batch vs Live Traffic Isolation

Workload

This benchmark tests whether the llm-d-async dispatch budget gate protects live inference traffic from batch request interference. Two scenarios are compared on identical hardware:

ModelQwen/Qwen3-8B on 1x NVIDIA A100 GPU
Live trafficguidellm burst/idle cycles: N/A req/s for 60s (burst), 1 req/s for 120s (idle), 2 cycles
Batch load1000 requests submitted at start (idle), another 1000 submitted during first burst
Batch requests~2000 random input tokens, no output cap (defeats prefix caching)
PatternIDLE → BURST → IDLE → BURST

Sync (no gate)

Batch-gateway processor sends requests directly to the inference gateway. Batch and live traffic compete for GPU capacity.

Gated (async dispatch)

Batch-gateway submits to a Redis queue. The async-processor dispatches only when the prometheus-budget gate is open (GPU utilization below threshold).

Conclusion

Without the dispatch budget gate (sync), the batch processor sends 1000 requests directly to the inference gateway during burst, competing with N/A req/s of live traffic for GPU compute. During burst phases, 0 of 0 live requests completed in time (TTFT N/A), while 0 batch requests consumed GPU capacity that could have served live traffic.

With the prometheus-budget gate, the async-processor monitors GPU utilization via Prometheus and holds back batch requests when the inference endpoint is saturated. During burst, only 210 batch requests were dispatched, allowing 3012 of 3176 live requests to complete (TTFT 211.6 ms). Batch work shifts to idle periods (201 requests processed during idle) when GPU capacity is available.
