Batch vs Live Traffic Isolation

Workload

This benchmark tests whether the llm-d-async dispatch budget gate protects live inference traffic from batch request interference. Two scenarios are compared on identical hardware:

ModelQwen/Qwen3-8B on 1x NVIDIA A100 GPU
Live trafficguidellm burst/idle cycles: 8 req/s for 300s (burst), 1 req/s for 120s (idle), 2 cycles
Batch load1000 requests submitted at start (idle), another 1000 submitted during first burst
Batch requests~2000 random input tokens, no output cap (defeats prefix caching)
PatternIDLE → BURST → IDLE → BURST

Sync (no gate)

Batch-gateway processor sends requests directly to the inference gateway. Batch and live traffic compete for GPU capacity.

Gated (async dispatch)

Batch-gateway submits to a Redis queue. The async-processor dispatches only when the prometheus-budget gate is open (GPU utilization below threshold).

Conclusion

Without the dispatch budget gate (sync), the batch processor sends 1000 requests directly to the inference gateway during burst, competing with 8 req/s of live traffic for GPU compute. During burst phases, 2339 of 2401 live requests completed in time (TTFT 237.4 ms), while 176 batch requests consumed GPU capacity that could have served live traffic.

With the prometheus-budget gate, the async-processor monitors GPU utilization via Prometheus and holds back batch requests when the inference endpoint is saturated. During burst, only 79 batch requests were dispatched, allowing 2350 of 2400 live requests to complete (TTFT 222.6 ms). Batch work shifts to idle periods (43 requests processed during idle) when GPU capacity is available.
